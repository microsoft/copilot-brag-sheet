Set up once

Requires Node.js 18+ and the GitHub Copilot CLI with an active Copilot subscription. Use a current CLI with experimental extension support. No npm install or separate plugin account is needed.

GitHub-backed plugin Recommended

Run these commands in PowerShell, macOS Terminal, or a Linux shell.

copilot plugin marketplace add microsoft/copilot-brag-sheet
copilot plugin install copilot-brag-sheet@brag-sheet
copilot --experimental

Approve the extension's hooks when prompted. Open /extensions manage and confirm copilot-brag-sheet is running before relying on capture. The extension API is experimental; behavior can vary by CLI version and launch mode.

Already using the older installer? Close your CLI sessions and move the old copilot-brag-sheet folder out of your Copilot home's extensions directory. Keep it as a fallback; do not run both copies. Leave your separate work-data directory untouched. Install into the same CLI profile you use for work.

Need another installation method? See the alternative installers and troubleshooting guide.

Update or remove the plugin

Refresh the marketplace and plugin, then restart Copilot CLI:

copilot plugin marketplace update brag-sheet
copilot plugin update copilot-brag-sheet@brag-sheet

To remove it, run copilot plugin uninstall copilot-brag-sheet@brag-sheet. Your saved records are stored separately; uninstalling the plugin does not remove them.

Try it with synthetic work

Five minutes, a disposable project, and no real work information. See a file change become an activity record, then save an outcome and generate a draft.

  1. Start a separate demo session. Follow the PowerShell demo setup to use a temporary data directory with git backup off. This keeps sample entries out of your real history.
  2. Create evidence. Ask Copilot: "Create demo-evidence.txt containing 'Synthetic demo: startup benchmark, before 10 minutes, after 6 minutes'. This is demonstration data, not a real achievement."
  3. Check capture. Ask it to read the current session JSON in the demo directory, confirm the filename appears in filesCreated or filesEdited, and show the capture counters. Do not save an accomplishment yet.
  4. Save the result. Ask: "Save a synthetic demo accomplishment: improved fixture startup. Category: tooling. Impact: synthetic benchmark decreased from 10 to 6 minutes. Evidence: demo-evidence.txt. Tag it demo."
  5. Generate and inspect. Ask: "Generate my work log, then draft a short review paragraph using only the saved demo entry. Keep the synthetic label, cite the evidence, and do not invent delivery status or additional metrics."

Confirm the entry exists in the saved JSON and generated Markdown, not just in the assistant's reply. Follow the walkthrough's cleanup step after exiting the demo.

Illustrative output, not a real achievement: In the synthetic fixture, startup time decreased from 10 to 6 minutes (evidence: demo-evidence.txt). No production or customer impact has been established.

Make the record useful as you work

Automatic capture remembers activity, not business impact. At a meaningful milestone, say "brag" and add what changed, your contribution, who benefited, the observed result, and a source link you are allowed to retain. If the outcome is not known yet, say so.

  • brag
  • log work
  • save accomplishment
  • what did I ship
  • review my work
  • summarize my impact
  • generate work log
  • prep my brag sheet
  • promo packet
  • perf review
  • self-review
  • weekly recap
  • monthly summary
  • what did I do this quarter

Records live in your OS app-data directory as structured JSON. Work outside the active CLI session is not captured automatically: add it manually or explicitly request a scoped backfill. File counts alone are not accomplishments.

Start review season with evidence

Use your saved records to prepare a draft, not a claim that every activity shipped. Agree on the review period and ask Copilot:

Use my saved brag-sheet records for the agreed review period. Group related work into impact themes. Separate my contributions from team outcomes, cite supporting entries or source links, and flag missing evidence. Do not infer business impact from file counts or invent metrics. Show me the draft before saving or sharing anything.

Review the dates and sources, remove sensitive details, and edit the draft in your own voice. The plugin provides records and a generated work log; your AI host helps write the narrative.

Local records. Deliberate sharing.

The plugin stores records on your machine and emits no telemetry of its own. That does not make AI processing offline or make every backup destination appropriate.

  • Use an approved host and account. Review tools return saved content to your AI host. Follow your organization's rules for the information you process.
  • Keep secrets out. Do not include credentials, raw customer data, or unnecessary sensitive details. Formatting sanitization is not secret redaction.
  • Leave git backup off unless approved. Backup is optional. A private personal repository is not automatically a suitable destination for employer information.
  • Inspect before sharing. Check generated logs and drafts. Use synthetic data in demos, screenshots, and public issues.

Capture depends on the experimental host API and can be incomplete. Check session records and capture counters rather than assuming every action was recorded. See the security model and limitations.

Why an extension, not just a SKILL.md?

If you've seen the brag-sheet skill listed elsewhere — that's the LLM guidance file. It's a prompt that tells the agent how to think about your work. This repo ships the prompt plus the extension that actually makes it happen.
